## Status Classification Key (Per Audit Section 4)

Every functional capability below is classified into exactly one of the six required statuses:
- **`implemented and independently demonstrated`**: Implemented in reachable code and independently verified in this audit by live execution, negative tests, and reproducible evidence.
- **`implemented but unverified`**: Code exists in the repository, but end-to-end verification is blocked or unexecuted in the current runtime.
- **`partial`**: Core mechanisms work for specific bounded cases, but material gaps, hardcoded domain limits, or bypasses prevent general-purpose reliability.
- **`broken`**: Implementation fails its stated invariant or produces actively wrong behavior under normal or negative inputs.
- **`design only`**: Documented in architecture specs or schemas without a working implementation.
- **`out of scope`**: Explicitly excluded by hardware, deployment, or administrative boundaries.
